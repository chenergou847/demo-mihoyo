## 二、采集

```powershell
# 关键词用逗号分隔；--since 控制评论日期下限；--max-videos 控制取样视频数
python 脚本/collect_bilibili.py `
    --keywords "幽境危战,原神 深境螺旋,原神 角色养成" `
    --pages 3 --max-videos 170 --since 2026-08-01 `
    --out 原始数据/bilibili_windowed.csv
```

**四个必须做对的地方**：

1. **先取会话 cookie，再调搜索接口** —— 否则返回 412；
2. **视频数据接口需要接口签名** —— 否则同样 412；
3. **必须加日期闸门** —— 热门评论会长期停留在榜首，不加窗口限制会把几年前的评论混进来；
4. **抓不到一律记 `null` + 原因码，不估算**。

**采集产物**：一平台一个文件，落在 `原始数据/` 下。

**原始文件建议列名**：

| 列 | 含义 | 例 |
|---|---|---|
| 平台 | 来源平台 | B站 |
| 用户编号 | **匿名编号**，不要写昵称 | U0001 |
| 内容 | 原始文本（帖子/评论） | "……" |
| 链接 | 原帖 URL | https://... |
| 日期 | 发表时间 | 2026-10-01 |
| 点赞数 | 如可见 | 128（不可见则留空） |
| 分层 | 自报/推断的玩家分层 | 硬核 / 中度 / 萌新 |

## 三、分析流程（五步）

| 阶段 | 输入 | 产出 | 关键口径 |
|---|---|---|---|
| ① 收集与统一 | 原始 CSV / MD / TXT | 观察表（14 列） | 一行 = 一条观察；逐字稿按「发言人标签+冒号」切分 |
| ② 主题编码（人工） | 观察表 | 填好 `theme` 的观察表 | **主题从数据里浮现，不预设类目** |
| ③ 汇总与分层 | 观察表 | 发现表 + 频次×影响矩阵 | 按**去重用户频次**（不是条数）汇总；证据分 0–6；置信度 高/中/低；四象限 |
| ④ 机会测算 | 机会输入表 | 带区间的排序 | 影响分 = 可触达用户数 × 频次 × 严重程度（+ 证据强度 / 战略契合 / 可行性） |
| ⑤ 报告装配与自检 | 全部 | 六段报告 + 检查结果 | 六段：研究概览 → 关键发现 → 人物画像 → 机会领域 → 建议 → 待解问题；引用必须逐字 |

**观察表 14 列**（编码结果的机读格式，`数据样例_已脱敏.csv` 即由此裁剪而来）：

```
observation_id, source_id, source_type, participant_id, segment, theme, observation,
quote, behavior, pain_point, context, intensity, impact, evidence_kind
```

**本卷实际执行到哪一步**：①②③ 与 ⑤ 的自检已完成。
**④ 机会测算未做** —— 缺「可触达用户数」（没有游戏内数据），强行做出来只是伪精确，
所以本卷只给相对严重度与受影响人数（理由见主报告第 4 节）。

## 四、分析纪律（红线）

- ❌ **不代笔、不杜撰**：不生成主题 / 结论 / 建议；引用必须逐字。
- ❌ **不预设类目**：主题必须从数据里浮现；未编码的行会被排除，而不是被猜一个主题。
- ❌ **不混淆行为与口头偏好**：`behavior` 与 `observation` 分列；材料多是"说的"时，置信度必须体现。
- ❌ **不给伪精确**：机会测算一律用区间。
- ✅ **先预览再落盘**：结构性写入先生成预览，确认后再落盘。
- ✅ **不删除矛盾**：来源互相矛盾是信号，写进「待解问题」。
- ✅ **发现偏差显式记账**：被排除的样本要记数量，不悄悄过滤。
- ✅ **保密**：`participant_id` 一律匿名编号；材料含个人信息先处理。

## 五、环境注意事项

1. 相对路径以**当前工作目录**为基准 → 建议在作品集目录下执行，或全部用绝对路径。
2. 判断成败看**退出码**与**产出文件**，不要只看输出尾部（提示语常打在最后，容易被误判成报错）。
3. 中文路径在控制台可能显示乱码（代码页 936），**数据无损**；设 `PYTHONIOENCODING=utf-8` 可得干净输出。
