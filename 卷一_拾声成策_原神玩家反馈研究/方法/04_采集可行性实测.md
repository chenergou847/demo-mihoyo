# 04 · 采集可行性实测（2026-10-06 本机实测，结论可直接复用）

> 目的：**在动手做作品集 A 之前，先把"数据能不能拿到"验证掉。**
> 方法：对每个候选渠道发一次真实请求，记录 HTTP 状态码与返回特征。全部结论都是实测，不是推测。

## 一、渠道可用性矩阵

| 渠道 | 直接抓取（DSH web_fetch） | 本机 Python 直连 | 结论 |
|---|---|---|---|
| **B站 · 视频搜索** `search/type` | ✅ 可用（HTTP 200，返回 JSON） | ⚠️ 裸请求 **412 风控**；**先取 cookie 后可用** | ✅ **主力渠道**（需 cookie 引导） |
| **B站 · 视频数据** `/x/web-interface/view` | ✅ 可用 | ⚠️ 412；**用 wbi 签名版 `/wbi/view` 后可用** | ✅ 可用（wbi 签名） |
| **B站 · 评论区** `/x/v2/reply` | ✅ 可用 | ✅ 可用，但**匿名仅返回约 3 条热门评论** | 🟡 可用但受限（见第三节） |
| 米游社 | ❌ 返回 `Loading...`（页面为 JS 渲染，评论不在首屏 HTML 里） | — | ❌ 直接抓取不可行；需浏览器或登录态导出 |
| NGA | ❌ HTTP 403「访客不能直接访问」 | — | ❌ 需登录 |
| 百度贴吧 | ❌ HTTP 403「百度安全验证」 | — | ❌ 反爬拦截 |
| 知乎 | ❌ HTTP 403 | — | ❌ 反爬拦截 |

## 二、可用的完整链路（已封装成脚本）

`采集脚本/collect_bilibili.py`（本机可跑，无登录）：

```
① GET https://www.bilibili.com/            → 取 buvid3 / b_nut cookie（否则 search 412）
② GET /x/web-interface/nav                 → 取 img_key + sub_key
   mixin_key = 查表重排后取前 32 位         → 对参数 wts 排序拼接 + md5 = w_rid
③ GET /x/web-interface/search/type?search_type=video&keyword=…&page=…
                                            → 视频清单：aid/bvid、标题、作者、播放、评论数、点赞、标签
④ GET /x/web-interface/wbi/view?aid=…&w_rid=…&wts=…
                                            → 该视频权威数据：播放/点赞/评论/弹幕/发布时间
⑤ GET /x/v2/reply/wbi/main?oid=…&type=1&mode=3&ps=20&next=0&w_rid=…
                                            → 评论区
⑥ 短评过滤（<6 字）+ mid 稳定匿名映射（U0001…）→ 落盘 CSV + 采集日志 JSON
```

**v1 试点结果（已跑通）**：请求 15 / 成功 15 / 失败 0。

## 三、关键限制：匿名只能拿到「约 3 条热门评论/视频」

**实测证据**：
```
aid=117325151998016（原神7.1幽境危战机制详解，评论数 3371）
  page=1  code=0  replies=3  all_count=3371  is_end=True  next=2
```
→ `is_end=True` 而 `all_count=3371`：**不是分页结束，而是匿名访问被截断**。
换 `mode=2`（按时间）、换传统 `/x/v2/reply?sort=0/2`、翻到第 2/3 页，均返回 0 条。

**这意味着什么（必须写进报告）**：
- 匿名样本偏向**高赞、高共识、易传播**的表达（热门评论排序），**不代表评论区全量分布**；
- 因此取数策略必须是**铺量**：多关键词 × 多视频 × 每视频 3 条 → 靠"视频数量"堆样本量；
- 定量侧用**视频级指标**（播放量、评论数、点赞数）做声量，定性侧用**评论文本**做主题，
  两者**不可互相换算**（不能说"3 条评论代表 3371 条的态度分布"）。

### 解锁全量翻页的唯一正当方式

用**你自己已登录的浏览器 cookie**（Netscape 格式），交给脚本 `--cookie-file` + `--full-paging`：
```powershell
& $py ".\采集脚本\collect_bilibili.py" --keywords "幽境危战,原神7.1" --max-videos 40 `
    --cookie-file ".\cookies.txt" --full-paging --out ".\原始数据\bilibili_full_20261008.csv"
```
> cookie 获取可参考参考工具集里的 `video-view-count-scraper/scripts/export_cookies.py`。
> ⚠️ cookie 是敏感凭据：只放本机、不要提交到任何仓库、用完即弃。

**为什么值得做**：全量翻页能把样本从"每条视频 3 条热门评论"升级为"按时间连续抽样"，
样本偏差显著降低，报告可信度上一个台阶。**这是把作品集从"能看"做到"专业"的分水岭。**

## 四、对行动计划的修正（相对 `03_行动计划.md` 的 P2）

| 原计划 | 实测后的修正 |
|---|---|
| A2 采集覆盖米游社/B站/贴吧/小红书多平台 | **主力改为 B站**（唯一稳定可自动采集的渠道）；米游社/贴吧/小红书改为**人工导出辅助**（你手动复制粘贴/截图，我来编码） |
| 目标 200–400 条来自 ≥100 名用户 | 保持目标，但实现方式改为 **≈80–150 个视频 × 3 条 = 240–450 条**；用户数按去重 mid 统计，会低于条数（需在报告中如实标注） |
| 平台间频次对比 | ❌ 取消（只有一个平台可自动采集）；改为**主题间对比 + 版本/角色间对比**，并声明单一平台局限 |
| 用 `agent-reach` 做社区阅读 | 降级为辅助：它对本机反爬渠道同样受登录限制；`web_search` 用于**发现**帖子（已验证能返回米游社/NGA/知乎链接），但**读取仅 NGA/知乎失败、B站成功** |

### 修正后的采集组合（建议）

| 来源 | 方式 | 预计样本 | 偏差与对策 |
|---|---|---|---|
| B站（自动） | `采集脚本/collect_bilibili.py`，铺量 80–150 视频 | 240–450 条 | 偏热门/高赞 → 靠视频数量与主题覆盖摊薄；声明局限 |
| B站（可选深度） | 提供登录 cookie + `--full-paging` | +数百条 | 偏差最小，**强烈建议** |
| 米游社（人工） | 你自己刷 2–3 个热门帖，把评论复制到一个 txt/csv 给我 | 50–100 条 | 米游社玩家结构更"日常向"，可对冲 B站攻略向偏差 |
| 1v1 小样本测试 | 作品集 B 的 6–10 名真实玩家 | 6–10 人 | 深度 > 广度，补充"行为证据"（behavior），提升证据分 |

> **方法论加分点**：把"为什么只采 B站"和"匿名 3 条上限"写进报告的口径与局限章节——
> **主动声明数据边界，比假装样本完美更专业**，这正好命中 JD 的"逻辑分析和信息提炼能力"。

## 五、合规与隐私（照此执行）

1. 只采**公开可见**内容；不绕过登录、不破解风控签名之外的权限（wbi 是公开接口的正常签名）。
2. 落盘**不含昵称、不含 mid**；`用户编号` 为稳定匿名映射（U0001…）。
3. 报告引用**逐字但截短**，不出现可定位到个人的信息。
4. 请求间固定延时 1.2–1.6 秒，不做高并发；单次采集请求量控制在数百以内。
5. 该数据集仅作**个人求职作品**，不公开发布、不用于任何商业用途。

## 七、首轮采集暴露的第二个缺陷：时间窗口失控（已修复）

**第一次铺量采集（80 个视频）跑通后做的数据体检结果**：

| 项 | 实测值 | 判断 |
|---|---|---|
| 行数 / 视频数 / 去重用户 | 235 / 80 / 233 | ✅ 达到 200–400 目标 |
| 每视频条数分布 | 3 条 × 75 个视频、2 条 × 5 个视频 | ✅ 与"匿名上限 3 条"一致 |
| 请求成功率 | 175 请求 / 172 成功 / **0 失败** | ✅ 稳定 |
| 昵称、mid 泄露 | **无**（字段仅 平台/来源视频/关键词/用户编号/内容/链接/日期/点赞数） | ✅ 合规 |
| **评论日期范围** | **2022-07-29 ~ 2026-10-06** | ❌ **与"近 2 个版本"口径严重不符** |
| 内容性质抽样 | 前 8 条里有 5 条是玩梗/剧情吐槽，而非玩法反馈 | ⚠️ 关键词过宽导致主题漂移 |

**缺陷根因**：热门评论（mode=3）会**长期停留在榜首**，所以从"当前版本视频"里取热门评论，
仍会捞到几年前的评论；同时 `--keywords` 里放了"原神7.1"这类宽词，把 PV/剧情视频的高赞玩梗评论也带了进来。

**修复动作（已写入脚本）**：
1. 新增 `--since YYYY-MM-DD` 参数：早于口径窗口的评论**排除并计数**（`dropped_out_of_window`），
   而不是悄悄留在样本里 —— 对齐 `PLAYBOOK.md`"口径未定不取数"与"取不到写 null + 原因"的纪律。
2. 关键词改为**玩法/系统/养成/活动导向**，剔除 PV/剧情类宽词。
3. 扩大视频数量（170 个）以补偿窗口过滤带来的样本损失。

**修复后重跑命令**：
```powershell
& $py ".\采集脚本\collect_bilibili.py" `
    --keywords "幽境危战,原神 深境螺旋,原神 角色养成,原神 太肝,原神 强度焦虑,原神 活动 建议" `
    --pages 3 --max-videos 170 --since 2026-08-01 `
    --out ".\原始数据\bilibili_windowed_20261006.csv"
```

> **这条经验本身就是作品集的加分素材**：面试时讲"我发现热门评论排序会让时间窗口失控，
> 所以加了日期闸门并把排除量显式记账" —— 比任何"我对数据敏感"的自我评价都有说服力。
