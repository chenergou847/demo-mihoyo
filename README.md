## 这个仓库是什么

把「玩家在说什么」变成「下一版该改什么」——用同一套可复现的方法做两件事：

| | 卷名 | 做什么 | 规模 |
|---|---|---|---|
| 纵深 | **卷一《拾声成策》** | 一个产品做到透：采集 → 主题编码 → 优先级矩阵 → 迭代建议 | 402 条评论 / 395 名用户 / 141 个视频 |
| 横向 | **卷二《同源异流》** | 把同一套口径迁移到第二个产品，检验哪些经验可迁移 | 对照 353 条评论 / 347 名用户 / 121 个视频 |

### 两个卷名的来由

- **拾声成策**——**拾**集玩家之**声**，**成**为迭代之**策**。对应卷一从原始评论到 12 条带决策状态建议的完整链路。
- **同源异流**——两款游戏同属开放世界 RPG、同平台、同时间窗、同口径，**15 个共有主题**是为「同源」（品类共性）；
  而各自的诉求结构与鸣潮特有的「信任与付费公平」诉求簇，是为「异流」（产品特异）。
  这个名字本身就是卷二的结论。

---

## 两卷的核心结论

### 卷一《拾声成策》

> **声量最大的问题，往往不是最该先改的问题。**

- 「强度膨胀与版本平衡焦虑」声量最高（51 人），但平均严重度仅 **2.17**、无人给 5 分，行为证据只有 3 条 → 属**预期管理**问题；
- 「深渊 11 层镇石机制」只有 9 人提及，平均严重度却达 **3.89（全表最高）**，7 人给 4 分以上 → 属**机制修复**问题。
- 高难内容的拦阻点不是操作水平，而是「账号里没有当期体系角色」：27 人讨论中有 **14 人（51.9%）给出放弃/失败/降档的行为证据**。
- 样本中 **36.7%（145/395）的发言并不构成产品反馈**（玩梗、闲聊、代肝交易等），已单独剥离并披露。

### 卷二《同源异流》

> **品类决定玩家问什么，产品与社区生态决定他们最不信什么。**

- 两游戏**共有 15 个主题**（占各自主题体系的 88% / 75%），平均严重度几乎一致（2.07 vs 2.08）→ 玩家诉求结构高度同构，**跨产品迁移经验的前提成立**；
- 但鸣潮有 **5 个特有主题**，其中 3 个属「付费与信任」类（累充定价争议 4.8%、概率暗改质疑 2.4%、Bug 与故障补偿 2.0%，合计约 **9.2%**），原神侧本窗口**完全没有对照物**；
- 「排期陷阱」两边都有但性质不同：原神是**机制与设备**类（移动端容错 +13、镇石机制 +11），鸣潮是**信任与沟通**类（官方沟通 +18、故障补偿 +16）。

## 方法与可复现性

| 环节 | 做法 |
|---|---|
| 口径 | 先定口径再取数：平台、时间窗、纳入排除规则、去重规则全部写在报告开头 |
| 采集 | 自建公开数据采集器（cookie 引导 + wbi 签名 + 日期闸门 + 含日期窗口过滤）；两游戏同平台、同时间窗、同参数 |
| 编码 | 逐条主题编码，**类目从数据浮现**；跨游戏采用**锚定编码**（同一语义复用同名主题，落不进的才新建特有主题），保证可比 |
| 分析 | 按去重用户计频次、区分「行为证据」与「口头表达」、构建频次×影响矩阵与声量-严重度错位 |
| 质检 | 引用逐字全量机检、机械探针交叉核验、量级上界比对、**样本重叠敏感度检验** |
| 披露 | 主动写明样本偏差与三处真实缺陷（详见下节） |

## 我主动发现并披露的三个问题

讲结论容易，讲自己哪里出错过更难——这三条都写进了交付件，而不是悄悄修掉：

1. **时间窗口失控**：热门评论会长期停留在榜首，导致首轮样本跨了 2022–2026。加入日期闸门后，把**被排除的 97 条显式记账**，而不是直接过滤。
2. **跨游戏编码边界严格度不一致**：人工编码得出非反馈占比为原神 36.7% / 鸣潮 28.5%，而**同一套机械探针**给出的是 46.3% / 47.8%——探针认为两边噪声水平几乎相同，说明该差距主要来自**编码严格度**而非社区差异。据此限定结论：只采用方向稳健且 |结构差| ≥ 5pp 的差异。
3. **样本不独立**：两个数据集有 **25 条逐字相同的评论**（源于 9 个被两边关键词同时命中的跨游戏视频）。做了敏感度检验——两侧同时剔除后，五条关键差异**全部保留且幅度略增**，说明重叠没有驱动结论。

## 关于数据：本仓库**不包含**什么，以及为什么

为尊重第三方内容与平台规则，以下内容**不进入本仓库**：

| 未包含 | 原因 |
|---|---|
| 原始评论数据（402 + 353 条逐字评论） | 属第三方创作内容，批量转载不合适 |
| 视频链接（BV 号） | 会指向具体创作者与视频，构成可定位信息 |
| 采集日志（含播放量/UP 主昵称） | 含第三方创作者昵称 |
| 含逐字引用列的完整编码表 | 同上 |

作为替代，每个卷提供 **`数据样例_已脱敏.csv`**：只保留**研究者自己撰写的观察概括**与主题/强度/影响/证据类型等代码字段，
不含任何玩家原话、昵称、UID 或链接——既展示了数据结构与编码口径，又不转载第三方文本。

**全部成品（PDF/HTML/报告）经脚本核验：不含任何玩家原话逐字文本，不含手机号、邮箱、身份证号等个人信息。**

## 使用说明

- 报告与分析文本：个人研究作品，**引用或转载请注明出处与本仓库链接**；不得用于商业用途。
- 代码（`脚本/` 下）：可自由参考使用；请注意各平台的 robots 与用户协议，采集时保持低频与合规。
- 分析结论为个人基于公开数据的判断，**不代表任何游戏公司立场**，也不构成对任何产品的评价结论。

## 局限（写在门口）

1. 均为**单一平台**（B站）数据，未覆盖米游社等日常向社区；
2. 匿名访问下每条视频仅可取约 3 条**热门**评论，样本偏热门、高共识、易传播，**不代表评论区全量分布，更不代表全体玩家比例**；
3. **无游戏内行为数据**，严重度来自评论文本打分，不等于通过率或留存；
4. 编码由单人完成，**未做第二编码者信度检验**；卷二鸣潮侧未做分群分析；
5. 卷二只对比了一款同类产品，**不能代表整个品类的规律**。
